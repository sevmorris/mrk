0.

Introduction

This manual describes the command-line tools in ~/bin. The tools fall into two groups. Standalone tools have no external dependency. mrk tools are symlinks into the mrk repository, and mrk manages them.

Note
All the tools are bash scripts or Go binaries. Two shared libraries supply the common behavior. scripts/lib.sh serves the mrk install-phase scripts. bin/lib/common.sh serves the standalone tools. See Section 3.1.
1.

Standalone Scripts

no external dependency
1.1

audio-mode standalone

audio-mode pauses the cloud sync services during a recording session. This prevents disk noise and latency.

audio-mode on [--icloud] [--gdrive] [--all]
audio-mode off
audio-mode status
  • on — Pauses Dropbox. The flags also pause iCloud and Google Drive. audio-mode first records which services run.
  • off — Resumes the services. audio-mode resumes only the services that ran before you gave the on command.
  • status — Shows the state of audio-mode and the state of each service.
  • audio-mode keeps its state in ~/.audio_mode_state.json. It uses jq to read and write this file.
  • audio-mode writes a log to ~/Library/Logs/audio-mode.log.
1.2

zoom-mode standalone

zoom-mode prepares the Mac for a Zoom recording session. It keeps the WiFi access point awake, stops sleep, stops a Time Machine backup, and starts audio-mode.

zoom-mode on
zoom-mode off
zoom-mode status
  • on — Does four things. It pings the default gateway every 30 seconds in the background, which stops the access point from dropping an idle connection. It falls back to 8.8.8.8. It runs caffeinate -d to stop display sleep and system sleep. It stops an active Time Machine backup. It then runs audio-mode on --all.
  • off — Stops the keepalive process and the caffeinate process. It then runs audio-mode off to resume the sync services.
  • status — Shows whether zoom-mode is active. It then runs audio-mode status.
  • zoom-mode keeps the background process IDs in ~/.zoom_mode_pids.
  • zoom-mode writes a log to ~/Library/Logs/zoom-mode.log.
1.3

nuke-mrk standalone

Caution
nuke-mrk deletes data. It asks you to confirm first. It does not uninstall the Homebrew packages, and it does not roll back the macOS defaults.

nuke-mrk deletes all the mrk files, so that you can install mrk again. It deletes ~/mrk, ~/.mrk, the mrk symlinks in ~/bin, and the dotfile symlinks in $HOME.

nuke-mrk
  • nuke-mrk shows the reinstall instructions when it completes.
1.4

snapshot standalone

snapshot exports the current app preferences as plists into ~/mrk/assets/preferences/.

snapshot [--brewfile] [--help]
  • snapshot writes the plists and then stops. It does not commit or push them, and gitignore excludes them.
  • snapshot does not scan the exported plists for secrets. Only snapshot-prefs and mrk-push do that.
  • --brewfile — also runs brew bundle dump. This command overwrites the comments in the Brewfile, so snapshot asks you to confirm first.
  • Apps: AlDente, Amphetamine, BetterSnapTool, Descript, Fission, HandBrake, Helium, Ice, iTerm2, ScreenFlow

mrk Scripts

symlinked from ~/mrk/scripts/
Note
The make install command symlinks these tools from ~/mrk/scripts/ and ~/mrk/bin/ into ~/bin. They are part of the mrk machine configuration system.
2.1

check-updates mrk

check-updates checks whether the mrk repository has new commits. It runs at most once every 7 days. If your copy is behind, it asks you to update.

check-updates
  • check-updates runs only in an interactive shell.
  • check-updates never waits for the network. It compares your copy against the last commit that git fetched, and it refreshes the remote in the background.
  • check-updates exits and shows nothing when your copy is current.
  • check-updates keeps the timestamp in ~/.cache/mrk/.
2.2

doctor mrk

doctor checks that ~/bin is on the PATH. The --fix option adds a PATH line to ~/.zshrc.

doctor [check | --fix | fix]
  • check (the default) — Shows the result and exits with status 0 or status 1.
  • --fix or fix — Adds the line to ~/.zshrc. doctor writes the line only when the line is absent, so you can run this command more than once. The line it adds first checks that ~/bin exists and that the PATH does not already contain it.
Note
To run the fix through Make, use make doctor ARGS=--fix. Make reads the bare form make doctor --fix as a Make option and fails.

fix-exec mrk

fix-exec sets the executable bit on the mrk scripts. It also sets the bit on the ~/bin symlinks that point into the repository. You can run fix-exec more than once.

fix-exec
2.4

hardening.sh mrk

Warning
hardening.sh changes system files, and it needs sudo. It writes the rollback script to ~/.mrk/hardening-rollback.sh before it changes anything. To undo the changes, run bash ~/.mrk/hardening-rollback.sh.

hardening.sh applies three optional macOS security settings. It asks you to confirm each one.

hardening.sh
  • Touch ID for sudo — Adds pam_tid.so to /etc/pam.d/sudo.
  • Immediate password after sleep — Sets the screensaver password delay to 0.
  • Firewall and stealth mode — Turns on the macOS application firewall. hardening.sh checks the firewall state and the stealth mode state separately, so it can turn on stealth mode when the firewall is already on.

hide_tm.sh mrk

hide_tm.sh hides the Time Machine backup volumes from the Finder sidebar.

hide_tm.sh [volume_name]
TM_VOLUMES="Vol1,Vol2" hide_tm.sh
  • The default volume name is TimeMachine.
  • To name more than one volume, give a comma-separated list. Use the argument or the TM_VOLUMES environment variable.

pull-prefs mrk

pull-prefs clones the private mrk-prefs repository into ~/.mrk/preferences/. If the clone exists, pull-prefs pulls it instead. The mrk-post-install command runs pull-prefs for you.

pull-prefs
2.7

snapshot-prefs mrk

Caution
snapshot-prefs scans every staged file for API keys and tokens before it commits. If the scan finds a match, snapshot-prefs stops and asks you to confirm. It does not ask when NONINTERACTIVE=1 is set or when there is no terminal — in those two cases it aborts. Read the reported lines before you answer.

snapshot-prefs exports the app preferences and pushes them to the private mrk-prefs repository. It exports plists for 14 apps. It also copies the Application Support files and the config directories.

snapshot-prefs
  • Apps: BetterSnapTool, Ice, iTerm2, Raycast, Stats, Loopback, SoundSource, Audio Hijack, Farrago, Piezo, Typora, Keka, TimeMachineEditor, MacWhisper
  • Application Support: Loopback (devices and routing), SoundSource (presets and sources)
  • Config directories: Calibre (~/Library/Preferences/calibre/). Calibre keeps a tree of files, not a defaults domain, so snapshot-prefs copies the files.
  • snapshot-prefs converts each binary plist to xml1 before it scans the file, because the scan cannot read a binary plist.
  • snapshot-prefs skips an app that is not installed, and it reports the skipped apps when it exits.

status mrk

status is a two-pane TUI dashboard. It shows the health of the mrk installation. The same binary also runs as mrk-status.

status
mrk-status --help
  • Left pane — nine checks, each with a ✓, ⚠ or ✗ mark: dotfiles, tool symlinks, macOS defaults, security hardening, backups, shell, PATH, Homebrew, and Brewfile packages.
  • Right pane — the detail lines for the selected check. The pane also shows the suggested fix command.
  • f — Run the fix command for the selected check.
  • r — Run all the checks again.
  • tab / ←→ — Move to the other pane.
2.9

sync mrk

sync compares the installed Homebrew packages against the Brewfile. It shows a picker for the new packages. It then adds the packages you select to the correct section, in alphabetical order.

sync [--dry-run | -n] [--commit | -c] [--prune | -p]
  • --dry-run — Shows the additions and the deletions. sync does not change the Brewfile.
  • --commit — Commits the Brewfile after sync updates it.
  • --prune — Deletes the Brewfile entries for the packages that you uninstalled. You select which entries to delete.
  • sync uses mrk-picker for the selection. If mrk-picker is absent, sync uses gum.
  • sync drops the names that ~/.mrk/sync-ignore lists. The file holds one formula name or cask name per line, and a # character starts a comment.
  • After you select the new packages in the picker, sync offers the packages you declined, so you can add them to the ignore list. It creates ~/.mrk/sync-ignore when you accept, and you can also write the file yourself. The offer changes only the ignore list, never the Brewfile. If you decline it, sync writes nothing and offers the same packages again on the next run. With --dry-run it shows the names but writes no file.
  • sync only adds to the ignore list. It keeps your comments, your blank lines and your order, and it adds each new name at the end.
  • If brew list fails, sync stops. An empty package list would make --prune mark every Brewfile entry for deletion.
  • sync writes the Brewfile to a temporary file first, and then moves it into place.
2.10

sync-login-items mrk

sync-login-items compares the system login items against the items that scripts/post-install tracks. It shows a picker, so you can add the new items or delete the old ones. It then updates scripts/post-install and docs/manual.md together.

sync-login-items [--dry-run | -n] [--commit | -c]
  • --dry-run — Shows the differences and your selections. sync-login-items writes no files.
  • --commit — Commits the changed files. The commit message has the form login-items: add X; remove Y.
  • sync-login-items uses gum for the multiple-selection list. If gum is absent, it asks a y/N question for each group.
  • sync-login-items reads the login items from System Events with AppleScript.
  • sync-login-items drops the names that ~/.mrk/login-items-ignore lists. The file holds one login-item name per line, without the .app suffix, and a # character starts a comment. Some apps add themselves back to the login items after an update, and the ignore list stops sync-login-items from offering them again.
  • After you select the new items to add, sync-login-items offers the items you declined, so you can add them to the ignore list. It creates ~/.mrk/login-items-ignore when you accept, and you can also write the file yourself. The offer changes only the ignore list. If you decline it, sync-login-items writes nothing and offers the same items again on the next run. With --dry-run it shows the names but writes no file.
  • sync-login-items only adds to the ignore list. It keeps your comments, your blank lines and your order, and it adds each new name at the end.
  • sync-login-items drops the ignored names from the new items only. A name in the ignore list does not delete an item that post-install already tracks. sync-login-items shows an app that is both tracked and ignored under "Ignored, but still tracked", and it offers to delete the app from scripts/post-install.
Caution
If System Events returns no login items, or if the AppleScript fails, sync-login-items stops and shows an error. It does not continue, because an empty list looks the same as a complete list of deletions, and sync-login-items would then offer to delete every tracked item. Give Automation access in System Settings → Privacy & Security → Automation, and then run the command again. If you really have no login items, edit the add_login_item block in scripts/post-install by hand.
2.11

mrk-install mrk

mrk-install is the mrk installer. It runs the setup phase, the brew phase and the post-install phase. Use it for a full bootstrap, or to run one phase again.

mrk-install [--brew | --post | --all] [options]
  • --brew — Run the brew phase.
  • --post — Run the post-install phase.
  • --all — Run all the phases, one after the other.
  • No flag — Run the setup phase only.
  • mrk-install passes the other options to the phase that you select.

mrk-setup mrk

mrk-setup is phase 1. It symlinks the dotfiles, symlinks the tools into ~/bin, sets the shell, installs oh-my-zsh and its plugins, and backs up the files that it replaces. You can run mrk-setup more than once.

mrk-setup [options]
2.13

mrk-brew mrk

mrk-brew is phase 2. It installs the Homebrew formulae and casks that the Brewfile lists.

mrk-brew [options]
2.14

mrk-post-install mrk

mrk-post-install is phase 3. It configures the apps that Homebrew installed. It imports the app plists, restores the Application Support files and the config directories, and registers the login items.

mrk-post-install
  • mrk-post-install continues when a step fails. It counts the failed steps and reports the total when it exits.
  • mrk-post-install imports a plist only when the app has no preferences yet, so it never overwrites a live configuration.
2.15

mrk-defaults mrk

mrk-defaults applies the macOS defaults for the Dock, the Finder, the keyboard and other system areas. It writes a rollback script to ~/.mrk/defaults-rollback.sh.

mrk-defaults [--with-trackpad]
  • No flag — Applies all the defaults except the trackpad gestures.
  • --with-trackpad — Also applies the trackpad gesture settings.
  • mrk-defaults continues when a write fails. It counts the failed writes and reports the total when it exits.
  • The rollback script covers the system defaults that mrk-defaults writes. It does not cover the browser preferences or the app preferences that mrk-post-install writes.
Note
To undo the defaults, run bash ~/.mrk/defaults-rollback.sh.
2.16

mrk-uninstall mrk

mrk-uninstall deletes the ~/bin symlinks that point into the repository. It then offers to run the defaults rollback script and the hardening rollback script. It keeps the dotfile symlinks and the ~/.mrk directory, and it does not uninstall the Homebrew packages. To delete everything, use nuke-mrk instead.

mrk-uninstall

bf mrk

bf is the Brewfile manager. It is a two-pane TUI: the sections are on the left, and the packages are on the right. bf reads the mrk Brewfile and writes to it. To use a different file, give its path as the argument. bf is a Go binary.

bf [BREWFILE]
bf --help | -h
bf --version
  • j/k · ↑/↓ — Move up and down.
  • tab · ←/→ — Move to the other pane.
  • a — Add a package.
  • d — Delete the selected package.
  • m — Move the package to a different section.
  • g — Turn the greedy option on or off. This applies to a cask only.
  • p — Delete the entries for the packages that you uninstalled.
  • / — Search the packages.
  • w — Write your changes to the Brewfile.
  • c — Commit the changes that you wrote.
  • q · ctrl-c — Quit.

mrk-menu mrk

mrk-menu starts any mrk task. It is a two-pane TUI, and it groups the commands into categories: Brewfile, Login items, Preferences, System state, Diagnostics, Maintenance, and Nuclear options. mrk-menu is a Go binary.

mrk-menu
  • j/k · ↑/↓ — Move up and down.
  • enter · → · l — Select the item, or start the command.
  • esc · ← · h — Go back.
  • 1–9 — Go to that entry in the active pane.
  • / — Filter every item in every category as you type.
  • ? — Show or hide the help panel.
  • q · ctrl-c — Quit.

mrk-picker mrk

mrk-picker selects Brewfile packages. It is a two-pane TUI, and it shows the categories, the packages and their descriptions. mrk-picker writes each package that you select to stdout as a formula:name line or a cask:name line, so another script can read them. The sync command uses mrk-picker when it is present. mrk-picker is a Go binary.

  • --brewfile PATH — Read this Brewfile. The default is Brewfile.
  • --installed-formulae LIST — A comma-separated list of the installed formulae.
  • --installed-casks LIST — A comma-separated list of the installed casks.
  • --skip-formulae — Leave the formulae out of the picker.
  • --skip-casks — Leave the casks out of the picker.
mrk-picker [--brewfile PATH] [--installed-formulae LIST] [--installed-casks LIST]
           [--skip-formulae] [--skip-casks]
2.20

mrk-push mrk

Caution
mrk-push scans every staged file for API keys and tokens before it commits. If the scan finds a match, mrk-push stops and asks you to confirm. It does not ask when NONINTERACTIVE=1 is set or when there is no terminal — in those two cases it aborts. Read the reported lines before you answer.

mrk-push commits the mrk repository and pushes it. It then deletes the old GitHub Pages deployments with the GitHub CLI. If you give no commit message, mrk-push asks you for one.

mrk-push "commit message"
mrk-push                # mrk-push asks for the message
  • mrk-push needs the gh CLI on the PATH.
  • Run mrk-push inside a git working tree.
  • mrk-push keeps the most recent GitHub Pages deployment and deletes the older ones.
2.21

maintain mrk

maintain does the periodic housekeeping for the mrk repository. It runs four steps in order.

maintain [--dry-run] [--keep=N] [--skip-check] [--help | -h]
  1. Delete the old GitHub Pages deployments. maintain keeps the newest N.
  2. Run git fetch --prune to delete the stale remote-tracking refs.
  3. Run make check to validate the repository.
  4. Compare each TUI binary against its source, and report the binaries that are out of date.
  • --dry-run — Show each step. maintain makes no API call, no git call and no make call. Step 4 still runs, because it only reads.
  • --keep=N — Keep the N most recent GitHub Pages deployments. The default is 10.
  • --skip-check — Do not run make check.
  • --help or -h — Show the usage text.
Caution
maintain asks you to confirm before it deletes any deployment. A low --keep value deletes more deployments. --keep=0 deletes the live deployment and takes the published page offline.
  • maintain needs gh, git and make on the PATH. It checks the gh login only when it will call the API.
  • maintain exits with status 1 when make check fails.
  • Run maintain through Make with make maintain. To pass an option, use make maintain ARGS=--dry-run.
2.22

dock-setup mrk

Caution
dock-setup deletes every item from the Dock before it adds the new items. It does not ask you to confirm, and it does not save your current Dock layout.

dock-setup fills the Dock with the apps that the DOCK_APPS list names. It then adds the Applications directory and restarts the Dock.

dock-setup
  • dock-setup needs dockutil. It installs dockutil with Homebrew when dockutil is absent.
  • dock-setup skips an app that is not installed, and it reports the total at the end.
  • To change the layout, edit the DOCK_APPS list in scripts/dock-setup.
  • Run dock-setup through Make with make dock.
2.23

ci-check mrk

ci-check runs the local validation for the repository. GitHub Actions runs the same script.

ci-check
  1. Run check-picker-desc.
  2. Run shellcheck on every bash script in scripts/ and bin/. ci-check skips scripts/adventure-prologue.
  3. Run go test in the five tool directories: picker, bf, mrk-status, mrk-menu and theme.
  • ci-check shows a warning and skips step 2 when shellcheck is absent. Install it with brew install shellcheck.
  • Run ci-check through Make with make check. To also build the TUI binaries, run make ci.
2.24

check-picker-desc mrk

check-picker-desc verifies that mrk-picker has a description for every Brewfile package. It compares the Brewfile against tools/picker/main.go.

check-picker-desc
  • check-picker-desc exits with status 1 when a package has no description.
  • ci-check runs check-picker-desc first, so make check covers it.
2.25

adventure-prologue mrk

adventure-prologue is a text adventure. It is the prelude to the mrk installation in adventure mode. The setting is a 4.3BSD workstation in 1989. Find the setup script on the mounted floppy disk, and run it.

adventure-prologue
  • adventure-prologue exits with status 0 when you run the setup script. It exits with status 1 when you quit.
  • adventure-prologue exits and shows nothing when stdin or stdout is not a terminal.
  • make adventure runs adventure-prologue first. If you complete it, Make then runs the full installation with narration.

Shared Libraries

scripts/lib.sh · bin/lib/common.sh

mrk has two separate libraries. scripts/lib.sh serves the mrk install-phase scripts. bin/lib/common.sh serves the standalone ~/bin tools, and it supplies a small set of logging and utility functions.

Table 3.1-1. scripts/lib.sh — mrk install-phase scripts (setup, brew, post-install, defaults.sh, hardening.sh, sync, …)
FunctionPurpose
log() ok() warn() err() info()Writes a log line to stderr. The colors are cyan, green, yellow, red and plain.
dry() logskip() section()Writes a dry-run log line, a skip notice, or a section banner.
confirm()Shows an adventure-style > prompt. The default answer is yes: it continues for every answer except quit, exit, q, n and no. It returns yes when NONINTERACTIVE=1 is set or when there is no terminal.
sudo_refreshExtends an active sudo session. It never asks for a password.
check_macosExits when the operating system is not macOS.
setup_loggingCreates ~/.mrk. Rotates ~/.mrk/install.log when the log is larger than 10 MB.
mrk_mktemp / mrk_mktemp_dCreates a temporary file or directory. Uses an explicit template, because GNU mktemp rejects the BSD form -t mrk.
scan_for_secretsSearches files for API keys, tokens and private keys. Converts a binary plist to xml1 first. Returns non-zero when it finds a match.
require_clean_secretsRuns scan_for_secrets and gates the commit. Asks you to confirm a match. Aborts instead when NONINTERACTIVE=1 is set or when there is no terminal.
Note — lib.sh Environment Variables
NONINTERACTIVE=1 — Skips the confirm() prompts. Aborts the secret check instead of asking.  ·  DRY_RUN=1 — Makes dry() label an action instead of reporting it as complete.
Table 3.1-2. bin/lib/common.sh — standalone bin/ tools (audio-mode, zoom-mode, …)
FunctionPurpose
ok() warn() err() info()Writes a log line. info() writes to stdout, and the others write to stderr.
is_runningChecks whether a process that matches a pattern runs.
require_cmdReports an error when a listed command is absent.
