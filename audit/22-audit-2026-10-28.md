## Z-1 — snapshot-prefs `--check` says "nothing new" for an app it could not read (MEDIUM)

BIN-1 (`mrk-usage.html:728`) says that `--check` "exits 0 when it can tell, 1 when it refuses".
Two cases exit 0 when it cannot tell.

**Case 1: a container that macOS does not let the process read.** `snapshot_plist`
(`snapshot-prefs:254-287`) asks `prefs_source` (`lib.sh:1184-1191`) for the domain to export.
When `~/Library/Preferences/<id>.plist` is absent, it is the bare domain, which `defaults` reads
from the app's container. On this Mac that is Keka: its container has a `Data/Library/Preferences`
directory, and `~/Library/Preferences/com.aone.keka.plist` is absent.

`defaults.sh` records what happens without access (`:233-243`). A launchd job with neither
permission read TextEdit's key as nodomain. So `defaults read com.aone.keka` fails, and
snapshot-prefs says this at `:268`:

```
  ▸ Skipping Keka (no preferences here yet — the saved copy is kept)
```

There is no `domain_denied` test here, as `defaults.sh` has. Reproduced in the copy, with a stub
`ls` that refuses the container's Preferences directory and a stub `defaults` that reads no
domain: exit 0, no line for Keka, and that message on stderr.

**Case 2: a failed or timed-out export.** `:270-280` adds the app to `SNAPSHOT_SKIPPED`, and
`on_exit` (`:137-142`) warns on stderr. The exit status stays 0. Reproduced with a stub whose
`export` of `io.github.sevmorris.Alpha` fails:

```
rc=0
--- stdout
repos.tsv		added
  ⚠ failed to export io.github.sevmorris.Alpha — skipped
  ⚠ Skipped 1 app(s) — export failed or timed out: io.github.sevmorris.Alpha
```

**Effect.** mrk-status (`daily.go:309-325`) and Dipstick's App Preferences pane read the exit
status and the lines, not stderr. They show "nothing new to snapshot" for an app whose changes
they could not see. The real run from Dipstick's console skips Keka in the same way, commits the
rest, and pushes. The saved copy of Keka stays, so nothing is lost. But the panel whose job is to
say what the next Mac would not get says that nothing is missing.

The condition for case 1 is Dipstick without permission to get the data of other apps. The
manual (`manual.md:503`) tells the owner to give it. Inference: whether this Mac's Dipstick has
it was not checked, because a check could start a macOS prompt.

**Fix.** Two parts:
- In `snapshot_plist`, test the container as `domain_denied` does, before the read. Say that
  macOS refused it, and do not say "no preferences".
- In `--check`, show an app that the run could not read, as an exit 1 or as a new word in the
  third field. The contract allows a new word. The choice is D-2.

## Z-2 — mrk-status does not follow the reader rule that BIN-1 sets (LOW)

BIN-1's "The --check Lines" (`mrk-usage.html:530`) says: "When stdout has lines and the program
can read none of them, the program must show an error, not an empty list." mrk-status is one
such program, and it does not:
- `checkLines` (`daily.go:217-219`) drops a line with fewer fields than it needs, with no count.
- The readers drop a word they do not know. `readDefaultsDrift` (`:470-483`) counts an unknown
  state as neither set nor unset. `readLoginDrift` (`:364-373`) and `readBrewDrift` (`:286-295`)
  drop an unknown action.
- When no line is read, the panels show ✓: "The Brewfile matches what Homebrew has installed"
  (`:676`), "App preferences: nothing new to snapshot" (`:791`) and "config/login-items.txt tracks
  every login item" (`:833`).

mrk-status ships with the scripts, so the two match in one checkout. They differ when the
binary is older than its source, which is a state that the Upkeep panel itself reports ("Older
than their source"). Dipstick follows the rule (`SettingsModel.swift:14-17`). No test gives
mrk-status a check of which it can read no line. `main_test.go:53` and `daily_test.go:209` each
mix one bad line with good ones.

**Fix.** In `checkLines`, return an error when stdout has lines and none has `n` fields. Count
the unknown words, and show a line when there are any.

## Z-3 — Exit 2 means two things, and the apps read it as one (LOW)

BIN-1's introduction says exit 2 means "the command line was wrong and nothing was attempted".
That is true. It covers an unknown option and also a value that a known option refuses.
Dipstick reads every exit 2 as an older mrk (`Mrk.swift:210-216`):

```swift
// Each script exits 2 for an option it does not know, and Dipstick
// passes only documented ones, so 2 means an mrk from before them.
let message = result.status == 2
    ? "\(command.script) does not take \(...): this mrk is older than Dipstick. Run make pull in \(...)."
```

Dipstick can pass a value that mrk refuses with exit 2. The names come from `--check`, with the
escapes undone. Reproduced in the copy:

```
rc=2 name=-Dash\ App   ✗ --add needs a login-item name.
rc=2 name=\ \ \        ✗ Not a login-item name: '   '.
rc=2 name=Two$'\n'Lines  ✗ Not a login-item name: 'Two…
```

- `sync-login-items:61-64` takes a name that starts with `-` for an option, so such an app can
  never be added. This is a defect of its own: System Events can list such a name.
- `:116-118` refuses a blank name, or one with a control character.
- `defaults.sh:120-133` refuses `--skip` with `--unskip`, or `--key` with `--revert`, for one key.
- `sync:135-149` refuses a name or a section that it cannot write. `tests/sync.sh:458-467` holds
  these to exit 2.

In each case Dipstick tells the owner to run `make pull`, which changes nothing. Barkeep has no
inference of its own. For an exit 2 it shows the last line of stderr (`MrkRunner.swift:211-216`).
`usage_error` (`sync:50`) prints that last line as "Run sync --help for the options.", so the
reason does not show (inference from the order of `err` and `info`).

**Fix.** In mrk: accept a name that starts with `-` after `--`, or as `--add=NAME`. In the apps:
take exit 2 as "older" only when stderr names the option, "unknown argument" or "Unknown
option". Better, a version handshake (O-2).

## Z-4 — Barkeep 1.15 does not undo the escapes, and splits lines by Character (LOW)

assets/CLAUDE.md:20 records the first half. It is still open: `MrkCandidate.parse`
(`Barkeep/Services/MrkRunner.swift:74-90`) is the same at `4df389d` and at `v1.15.0`. The two
commits after the tag change only `scripts/check-shared.sh` and `tools/dmg/`. No Swift file in
Barkeep names an unescape.
- A description, a section or a reason with a backslash shows it doubled. A tab or a newline
  shows as `\t` or `\n`.
- A name goes back to `sync --add`, `--ignore` or `--prune` as it came. Inference: harmless,
  because `sync:135` refuses a name that is not a package name, and Homebrew names hold no
  backslash.

The second half is new. `parse` splits on `"\n"` as a Swift Character, and `"\r\n"` is one
Character. A line whose last field ends in a carriage return joins the next line. With
`--details` the last field is the description from `tools/picker/descriptions.tsv`, and no reader
of that table refuses a carriage return (Z-6). The add or prune after it is lost.

**Fix, in Barkeep.** Split on Unicode scalars, as Dipstick's `MrkText.lines` does
(`TSV.swift:56-60`), and undo the three escapes in each field.

## Z-5 — Dipstick's decoder is stricter than the reference in two places (LOW)

`MrkText.unescape` (`Dipstick/Sources/Dipstick/TSV.swift:17-31`) follows the contract for what
mrk writes, with two differences from the Go reference (`daily.go:230-255`):
1. **It walks Characters.** A backslash before a combining mark is one Character, which is not
   `"\\"`. So is `t` or `n` before a combining mark, which is not `"t"` or `"n"`. Reproduced with a
   copy of the function: `x\t` + U+0301 and `x\\` + U+0301 both return nil, and `fields()`
   drops the whole line (`:39`). The Go decoder gives both back. mrk can write either: a tab or
   a backslash before an accent in a value of `defaults.tsv`, or in a key name of an app plist.
2. **It returns nil for any other escape, and for a trailing backslash.** The Go decoder keeps
   both. mrk never writes them, so this is only a difference.

Both apps read stdout as `String(decoding:as: UTF8.self)` (`Subprocess.swift:10`; Barkeep
`ScriptProcess.swift:11`). Invalid UTF-8 becomes U+FFFD, and a name sent back to a decision is
then not the name that mrk listed. Inference: no source that mrk reads gives invalid UTF-8 today.

**Fix, in Dipstick.** Walk `unicodeScalars` in `unescape`. The shared fixtures of O-1 would hold
all three decoders to one answer.

## Z-6 — A carriage return passes the encoder, and the readers of config/ differ on it (LOW)

**The encoder.** `mrk_tsv_escape` (`lib.sh:286-292`) escapes a backslash, a tab and a newline, and
passes every other byte. Its comment says "so mrk_tsv_fields gives TEXT back", and BIN-1's table
of lib.sh (`mrk-usage.html:1754`) says the same. That is false for a carriage return, an escape
character, DEL and the other control characters. `mrk_tsv_fields` (`:264-266`) refuses them:

```
mrk_tsv_fields rc=1 why=it holds a control character other than a tab
```

No `--check` line goes back through `mrk_tsv_fields`. The skip list does, but its domains and keys
cannot hold a control character (`defaults_row`). So no run breaks today. The comment and BIN-1
promise a round trip that does not exist, and a reader that trusts them can join two lines
(Z-4).

**The readers of config/.** A line that ends in a carriage return, as an editor writes CRLF:

| File | mrk | Dipstick |
|---|---|---|
| `dock.txt` | `X.app\r` does not end in `.app`, so it is a folder, `missing`, and `make dock` skips it (`dock-setup:111-114`) | the same: a folder (`DockList.swift:18`) |
| `login-items.txt` | the file is refused, exit 1 (`sync-login-items:154-179`) | the rows show; the name test fails silently (`LoginItems.swift:77-79`) |
| `defaults.tsv`, `defaults-skip.tsv`, `app-prefs.tsv` | the file is refused (`mrk_tsv_fields`, `app_prefs_why`) | not reached: `--check` exits 1 first |
| `tools/picker/descriptions.tsv` | accepted by `check-picker-desc` (`awk -F'\t'`), mrk-picker (`main.go:69-90`) and `sync` (`IFS=$'\t' read`); the carriage return stays in the description | Barkeep joins two lines (Z-4) |

Whitespace-only lines, comments and a missing final newline are read the same way by every
reader. ci-check holds the committed form of each of the six files: `dock-setup.sh:65-82`, the
`sync-login-items` and `plist-import-order` tests, `snapshot-prefs.sh` (byte order, each once),
`install-apps.sh:168-179` (byte order), and `check-defaults-desc` for the two defaults files. None
of them looks for a carriage return.

**Fix.** Correct the comment and BIN-1. Refuse a control character in `check-picker-desc`, and in
`dock.txt` as in `login-items.txt`. Optionally, escape `\r` too: a new escape is a contract
change, so that is D-5.

## Z-7 — No lock on the writers of config/ (LOW)

Each writer reads its file, writes a temp file and renames it over the original. A second
writer between the read and the rename loses the first one's change. Reproduced in the copy:
two `defaults.sh --skip` runs at once, each for its own key, ten times. All ten lost one key.

**What Dipstick queues** (read in its source):
- Two macOS Defaults switches: no. `decide` sets `busy` before its first `await`
  (`SettingsModel.swift:269-273`), and the switches are disabled while it is set.
- A console command, then any pane: no. The panes are disabled while the console runs
  (`SettingsView.swift:58-60`).
- A switch, then a console command: yes. Dock **Apply…** (`DockPane.swift:73-78`) and Prefs
  **Snapshot…** (`PrefsPane.swift:63-70`) do not check `isDeciding`. So `make dock` can run while
  `defaults.sh --revert` restarts the Dock, and `make snapshot-prefs` can export a half-changed
  domain.
- A switch and `defaults.sh --check`: yes. The Trackpad box and ⌘R start `load()`, which has no
  guard (`DefaultsPane.swift:113-116`). A slower, older check can show last. This only shows a
  stale state.
- A switch and a login-item decision: yes. They write different files.
- Two login-item decisions: inference, yes. `LoginItemsModel.decide` sets `busy` inside the task
  (`SettingsModel.swift:337-345`), so two clicks before the first task starts both run.
  `sync-login-items` then loses one of the two changes, as `--skip` did above.

Barkeep runs every check and decision through one queue (`MrkModeViewModel.swift:99-114`).

`sync-login-items` renames `config/login-items.txt` and then `docs/manual.md` (`:875-876`), in two
steps. A commit between the two holds a list and a sentence that disagree, and
`tests/sync-login-items.sh` then fails. The window is short.

**Fix.** A lock in lib.sh around each read-modify-rename, a lock directory beside the file,
taken with `mkdir`. Or, in Dipstick, one queue for every mrk command that writes. The choice is
D-4.

## Z-8 — Temp files, and what mrk-push stages (LOW)

- **Not beside the target.** `sync-login-items` writes its new list and manual in `$TMPDIR`
  (`:213`, `:801`) and moves them over the originals. The skip list, the Brewfile, the picker
  table and Dipstick's `dock.txt` use a temp file in the same directory. Here `$TMPDIR` and
  `~/mrk` are on one volume (device 16777232), so the move is a rename. On another volume, `mv`
  copies and deletes, and a reader can see half a file.
- **Not ignored.** `.gitignore` ignores `.Brewfile.*` alone. A temp file that a crash leaves
  behind shows as untracked: `config/defaults-skip.tsv.XXXXXX`,
  `tools/picker/.descriptions.tsv.XXXXXX`, and Dipstick's `config/.dock.txt.gearbox-<UUID>`
  (`DockList.swift:116`). bash runs the EXIT trap on SIGTERM, which Dipstick's watchdog sends,
  so only a SIGKILL or a crash leaves one.
- **mrk-push stages untracked files.** Its help says "untracked files are never committed"
  (`mrk-push:61`). mrk-status says the same (`daily.go:704`). But mrk-push runs `git add` on nine
  paths (`:155`, `:196-198`), and `git add tools` stages a file that git does not track:

  ```
  $ git add --dry-run tools
  add 'tools/picker/.descriptions.tsv.Ab12Cd'
  ```

  So a temp file that a crash leaves in `tools/` is committed and pushed. The PATHS list is older
  than the port. It does not name `config/`, so a new file there is not committed. Today every
  file in `config/` is tracked, so `git add -u` stages each change.

**Fix.** Make the temp files in the target's directory. Add their patterns to `.gitignore`. Make
mrk-push's help and mrk-status say what mrk-push stages, or stage only `git add -u` and the
files that mrk itself adds. In Dipstick, rename the temp file.

## Z-9 — A picker table with no final newline stops every description delete (LOW)

`picker_remove_descriptions` (`lib.sh:1427-1446`) checks its work by line count:
`want=$(( $(wc -l < "$table") - $# ))`. `wc -l` counts newlines. When the last line has none,
awk's output has one line more than `want`, and the function refuses. Reproduced:

```
✗ Expected 1 lines in tools/picker/descriptions.tsv after removing 1, got 2 — left it unchanged.
```

`picker_add_descriptions` reads the same file and adds the newline, so an add works.

Effect: `sync --prune NAME`, which Barkeep's Remove runs, writes the Brewfile first
(`sync:713`), then fails to delete the description and warns (`:719-724`). `check-picker-desc`
then fails on the orphan, and `--fix` fails in the same way. `check-picker-desc` does not look for
a final newline, so it names the orphan, not the cause. A hand edit can leave the file so.
Barkeep never writes it.

**Fix.** Count entries, not lines, or add the newline before the count.

## Z-10 — mrk-status `--json`: no document with no HOME; Homebrew found two ways (LOW)

- `main.go:897-901` exits 1 with no document when `os.UserHomeDir` fails, which on macOS means
  HOME is not set. BIN-1 (`:765`) says it "exits 1 only when it cannot write to stdout".
  Reproduced with `env -i`. Dipstick shows "mrk-status exited 1", which is right. The doc is not.
- `checkHomebrew` (`main.go:402-411`) runs `brew` from PATH. `brewBin` (`daily.go:185-197`) also
  tries `/opt/homebrew/bin/brew`. With Homebrew off PATH, the Installation panel says "Homebrew
  — Not installed" as an error, and the line below it says "Brewfile — 54 formulae and 62 casks
  tracked, all installed". Reproduced with `PATH=/usr/bin:/bin`. Dipstick gives mrk-status the
  login shell's PATH, so this needs its fallback environment (`ShellEnvironment.swift:25-38`),
  which adds `/opt/homebrew/bin`. Inference: not reachable from Dipstick today.

The JSON was valid in every other case tried: no git (`PATH=/bin`), a checkout that does not
exist, and an empty HOME with no `~/.mrk`.

**Fix.** Use `brewBin` in `checkHomebrew`. Add the HOME case to BIN-1, or fall back to the
password database.

## Decisions

### D-1 — What a switch's "off" puts back

`--revert` puts back the value from the first line for the key in
`~/.mrk/defaults-rollback.sh`. `write_default` never writes a second line for a key, so that is
the value before mrk first wrote the key on this Mac. A change that the owner makes by hand
between two "on"s is lost at the next "off". Reproduced with the stub store:

```
before mrk: WhenScrolling
  on:  Always   ·  off: WhenScrolling
by hand: Automatic
  on:  Always   ·  off: WhenScrolling
```

BIN-1 documents this, so it is not a defect. Options:
- keep it: "off" means "as before mrk"
- record the value before each `--key` in a second file, and let `--revert` put back the last one
- show in Dipstick the value that "off" will put back, from the undo line, before the switch moves

**Decided 2026-10-29:** keep it. "Off" means "as before mrk".

### D-2 — How snapshot-prefs `--check` says that it could not read an app

For Z-1. Options:
- exit 1 when any export failed, or any container was refused. Simple, but the pane then shows no
  line at all, where today it shows the lines it could read.
- a new word in the third field, such as `unread`, with the file and an empty key. The contract
  allows it. mrk-status and Dipstick pass over a word they do not know, so each needs a change
  to show it, and an older Dipstick shows nothing for it.

**Decided 2026-10-28:** the new word, `unread`, with exit 0.

### D-3 — Keep or delete `sync-login-items --manual`, and the manual's sentence

See opportunity 5. Deleting the sentence deletes the only writer of `docs/manual.md` among mrk's
scripts, which CLAUDE.md names as load-bearing.

**Decided 2026-10-29:** delete `--manual` and the sentence. The manual links to
`config/login-items.txt`.

### D-4 — Where the lock goes

For Z-7: in mrk, which protects every caller, Terminal included; or in Dipstick, as one queue for
every mrk command that writes. The two do not exclude each other.

**Decided 2026-10-28:** in mrk's lib.sh, a `mkdir` lock beside each file.

### D-5 — A carriage return in a field

For Z-6: escape `\r` as a fourth escape, which every decoder must then undo; or refuse it at the
source; or leave it and correct the docs. A fourth escape changes the contract, and an older
Dipstick passes over a line with an escape it does not know.

**Decided 2026-10-28:** refuse it in the lists, correct the docs, and add no escape.
