## BB-1 — Dipstick 0.10 runs every command in its console (LOW, wide)

Dipstick 0.10 (sevmorris/Dipstick#25, released 2026-11-07) draws mrk-picker, gum and mrk-menu in
its console. Its README says: "Every other fix runs in Dipstick's console, the full-screen ones
too … Nothing opens Terminal." The Commands pane runs the commands that mrk-menu `--json` marks
`terminal` in the console too. This Mac has Dipstick 0.13. `assets/CLAUDE.md` records the
change, from commits `084f689` and `7c94d84`. No other document does:

1. `README.md:128`: "`make sync ARGS=--push`, `make brew` and the mrk-menu button open a
   terminal", and the Commands pane runs a command "in the console, or in a terminal for those
   the list marks `terminal`".
2. `manual.md:496`, the Commands pane: "A command that the list marks `terminal` runs in a
   terminal: the commands of `sync` and `sync-login-items` …, `update-full` and `nuke-mrk`."
3. `manual.md:502-504`: "Dipstick runs most commands in its console", and "The console cannot
   show a full-screen list to select from. So a fix for a Make target that `scripts/mrk-contract`
   lists under `terminal` runs in a terminal. … The mrk-menu button also runs its command in a
   terminal."
4. BIN-1, the `terminal` key of mrk-contract (`mrk-usage.html:1782`): "Dipstick runs a fix for
   one of these targets in Terminal." The list is still in mrk-contract, for Dipstick 0.6 to
   0.9, as `assets/CLAUDE.md` says. The sentence should name those versions.
5. SMAC-1, the mrk-contract row of Table 2.7-2: "Dipstick also reads it to find the fixes that
   it must run in Terminal."
6. SMAC-2, the Commands pane: "A command there runs as it is shown, in the console of Dipstick
   or in Terminal."

No step in `CLAUDE.md` covers a change in a sibling app that mrk's documents describe. That is
why this reached `assets/CLAUDE.md` and nothing else.

**Fix:** say that Dipstick runs every command in its console from 0.10, and that the `terminal`
list is for 0.6 to 0.9. The manual's paragraph at `:504` keeps its Barkeep sentence. Add a row
to the first table of `CLAUDE.md`: a Dipstick or Barkeep release that changes what README or the
manual says about it.

## BB-2 — tidy-projects asks on a terminal, and the cautions do not say so (MEDIUM)

#160 (`0857225`): on a terminal, the tidy-projects report ends by asking which cleanups to
make. `a` makes every cleanup, `deploys` too. `s` makes every cleanup but `deploys`. Return
makes none. BIN-1 §2.39 and SMAC-2 step 5 describe the prompt. Two documents do not:

1. `manual.md:525`, the tidy-projects row, names `--apply` and `--check`, and not the prompt.
   The caution at `:532` says: "`tidy-projects --apply deploys` deletes GitHub Pages
   deployments, and a deleted deployment cannot come back. Run `tidy-projects` without
   `--apply` first, and read the report." That run now ends at the prompt, where `a` deletes
   deployments.
2. SMAC-1, "Caution — Four of These Delete Things" (`index.html:1082`): "without --apply it only
   reports, so run that first." On a terminal it does not only report.

The prompt shows its choices, so this is not a trap. But it is the case `CLAUDE.md` names: "A
destructive command gaining or losing a safeguard — its section, and the Caution beside it."
A caution that says a run is report-only must be true.

**Fix:** the manual's row names the prompt. The caution says to answer `s`, or press Return,
to keep the deployments. SMAC-1 says that on a terminal the report asks which cleanups to make,
and that `s` leaves the deployments alone.

## BB-3 — Calibre left the Brewfile, and nothing installs it (LOW, the owner's decision)

`676f811` removed the `calibre` cask and its picker description. Calibre is still on this Mac:
`/Applications/calibre.app`, version 9.18.0, from neither Homebrew nor the App Store (`mdls`
gives no `kMDItemAppStoreAdamID`, and `brew list --cask` has no calibre). snapshot-prefs still
saves its config ("Saved Calibre config (16 item(s))"). Phase 3 still restores the config, but
only when `/Applications/calibre.app` is there (`post-install:926`).

So on a new Mac, Phase 2 does not install Calibre, and Phase 3 skips the restore. The config
holds the DeACSM activation (`manual.md:308`), so it matters that the restore runs. No
document says to install Calibre by hand:
- The manual's "Write down the apps …" list (`manual.md:643`) names the App Store apps, and
  says to run Phase 3 again after you install them. It does not name Calibre.
- SMAC-1 §2.6, the migration checklist, is the same.
- The manual (`:139`) and SMAC-1 (`index.html:681`) describe the restore as if the app is
  always there.

**Decision for the owner:** was the cask removed so that Calibre updates from its own download?
If yes, name Calibre in the "install by hand" item of the manual and SMAC-1 §2.6, with the
App Store apps, and say to run `make post-install` again after. If no, put the cask back.
