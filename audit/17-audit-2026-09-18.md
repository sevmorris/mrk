## V-1 — `mrk-install --all` was a second, shorter definition of a full install (MEDIUM, FIXED)

`scripts/install --all` ran `setup`, `brew` and `post-install` itself. `make all` does four
things more:
- `fix-exec` first
- `build-tools` after, which builds mrk-picker, mrk-status and mrk-menu
- the closing notes: `exec zsh`, the mrk-prefs hint, and the App Store apps reminder

BIN-1 described `--all` as "all the phases", which was true and hid the difference.

**Fix.** `--all` now runs `make --no-print-directory -C <repo> all`, with any other flags as
`ARGS`, so the Makefile is the only definition of a full install. `/usr/bin/make` is a stub
that offers to install the Command Line Tools rather than failing. So without them `--all`
exits 1 before running anything, and points at Phase 1, which installs them.

**Test.** `tests/install-all.sh` runs with stubs of `make` and `xcode-select`, under
`/bin/bash` 3.2.57 and bash 5.3.20:
- `--all` runs `make all` in the repository
- one flag, and two flags on either side of `--all`, arrive as `ARGS`
- the missing-CLT path exits 1 and runs nothing
- `--help` runs nothing

A static check fails if `make all` stops listing `fix-exec`, a phase or `build-tools`.

### V-2a — A repository guard that passed from any other directory (LOW, FIXED)

The first draft of the pipe guard failed only when run from `~/mrk`. The cause was the idiom it
borrowed from `tests/macos-updates.sh`: `git -C "$REPO_ROOT" ls-files | xargs grep`.
`ls-files` prints paths relative to the repository, and grep resolves them against the
caller's directory. From the repository root, the guard works. From anywhere else, grep
behaves one of two ways:
- it finds no file, `2>/dev/null` silences it, and the guard passes having read nothing
- it finds a different checkout's file of the same name, which is what happened here

`ci-check` does not `cd`. `make check` and CI happen to start at the root, which hid this.
Shown with `softwareupdate -ia` planted in a scratch copy: the old `macos-updates.sh`, run from
`/`, printed "✓ no tracked script calls softwareupdate with --all" and exited 0. Both guards now
run their grep inside the repository.

## V-3 — `sync-login-items` wrote lines it could not read back (MEDIUM, FIXED)

It had not been exercised before: modules 15 and 16 left it alone to avoid the System Events
permission prompt. The harness avoids the prompt. It runs a copy of the repository under a
throwaway HOME, with `osascript` stubbed to print a fixture and `gum` stubbed to select
everything, inside a pseudo-terminal from `script`, because gum is called with `</dev/tty`.

**What held.** The first write was right every time:
- `post-install` parsed
- every generated line, run by bash, gave back its exact path, spaces, quotes, `$` and all
- apostrophes, commas and apps outside `/Applications` worked in both directions

**What did not.** The second run over an unchanged system should do nothing. It changed
things:

| Name | Second run |
|---|---|
| `Cash $App`, `` Tick`Tock ``, `Back\slash` | new *and* stale: the reader kept the escaping backslash, so it read `Cash \$App` |
| `Say "Hi"` | new: the reader's `[^"]+` stops at the escaped quote, so the line was never recognised. At the edge of the sorted block it would duplicate on every run |
| `Crème`, composed from System Events and decomposed in the path | new *and* stale, shown under the same name twice |

The writer escaped `\ " $ `` ` `` for bash. The reader was a bash regex, a second
implementation that knew nothing of it.

**Fix.** Tracked items are now parsed in Python, with the same path pattern and `unescape()` as
the rewrite. Names are compared in NFC on both sides. System Events' names are normalized as
they are read, and the tracked names from their paths. Paths are kept exactly as given.

**Test.** `tests/sync-login-items.sh` runs twelve awkward names through the whole cycle:
1. add them
2. `post-install` still parses, and every line round-trips through bash
3. the manual names them as written
4. a second run does nothing
5. removing them restores `post-install` and the manual byte for byte
6. a last run does nothing

| Mutation | Failing checks |
|---|---|
| `sync-login-items` at `main` | 2 |
| no NFC on the System Events side | 1 |
| no NFC on the tracked side | 3 |

The first draft missed the System Events mutation, because every fixture name from System
Events was already composed. A decomposed name with a composed path was added.

**Not covered:** an app whose login-item name differs from its bundle's file name. Tracked
names come from the path and system names from System Events, so such an app would be new and
stale on every run. No app here is like that.
