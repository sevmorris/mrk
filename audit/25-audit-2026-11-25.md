# Module 25 — After the macOS 27 upgrade (2026-11-25)

**Date:** 2026-11-25
**Audited:** mrk `e08b303` (PR #173) and sevmac `4303bf3` (PR #67), both level with origin.
**Mac:** M5 Pro, macOS 27.2.1 "Golden Gate" (26B131), Darwin 27.2.0. Xcode 27.2 (27B52),
Command Line Tools 27.2, Homebrew 7.0.16, Go 1.27.4.

**Why now.** `softwareupdate --history` shows macOS 27.2.1 installed on 2026-11-20 at 16:07,
from macOS Tahoe 26.7.3. Audit 24 ran on 2026-11-18, under 26.7.3, so nothing had checked mrk
on macOS 27. Module 18 asked whether mrk suits macOS 26 on this Mac. This module asks the same
of macOS 27. It also follows each finding into the other places that make the same claim.

**This began as a findings pass.** It changed nothing on the Mac or in either repository,
except this file. The owner took CC-2, CC-4 and CC-5 the same day, then decided CC-1, CC-3
and CC-6. See "Fix session" and "Decisions" at the end.

**Method:**
1. The gates, in a clone of `e08b303` in the session's scratch directory, under a throwaway HOME.
2. Every read-only mode on the live Mac: the six `--check` modes, `make status`, `make doctor`,
   and the dry runs of `setup`, `trim-services`, `dock-setup`, `maintain`, `macos-updates`
   and topgrade with mrk's config.
3. The state that an OS upgrade can reset, read directly: `/etc/pam.d/sudo` and `sudo_local`,
   the firewall, `LSQuarantine`, diagnostics submission, Software Update's automatic
   download, `/etc/shells`, the login shell, the launchd override database, the LaunchAgents,
   the login items (System Events and `sfltool dumpbtm`), TCC-dependent reads, and the crash
   reports since the upgrade.
4. The toolchain on macOS 27: Homebrew's bottles for every installed formula, the casks'
   `depends_on` and caveats, the Go binaries' load commands, the pyenv Python, the SDKs, and
   the signatures of the ten companion apps by the same checks `install-apps` uses.
5. Every OS command that mrk parses, run on 27 and compared with what the code expects:
   `socketfilterfw`, `launchctl print-disabled`, `launchctl load`/`unload` (with a throwaway
   agent), `softwareupdate --list`, `codesign`/`spctl`, `dockutil`, System Events.
6. Every tracked file outside `audit/` searched for a macOS version, a release name,
   `sw_vers`, `ProductVersion` and a runner label. Each hit was read against macOS 27.

**Headline: mrk runs cleanly on macOS 27, and nothing that the upgrade could reset was reset.**
The findings come from two other places:
- **Nothing in `CLAUDE.md` names an OS upgrade.** So the four pages that state the platform
  still say macOS 26, and CI still tests macOS 26. `ci.yml` carried its own reminder ("Bump
  this in the same change as that upgrade"), and the upgrade passed it by (CC-1, CC-4).
- **Apps changed beside the upgrade.** Logic Pro 12 arrived today under a new bundle name, so
  `make dock` would take Logic Pro out of the Dock (CC-2). Amphetamine is in
  `config/login-items.txt` and is not a login item (CC-3).

## CC-1 — CI tests macOS 26 (LOW, decision)

`.github/workflows/ci.yml:18-22`:

> The macOS this Mac runs, on Apple silicon. macos-latest was that on 2026-09-23, and it moves
> to macOS 27 when GitHub promotes it, while macos-updates keeps this Mac on 26 until its owner
> upgrades by hand. Bump this in the same change as that upgrade.
> `runs-on: macos-26`

The owner upgraded by hand on 2026-11-20. The latest run on `main` used `Image: macos-26-arm64`.
Every test passes there, so nothing is broken. But module 18 (M-4) chose this label so that CI
runs the OS of this Mac, and now it does not.

The bump the comment asks for cannot be made as written. `actions/runner-images` has no
`macos-27` label today. GitHub offers macOS 27 only as `xcode-27` (`xcode-27-arm64-Readme.md`:
macOS 27.0.1, 26A434, image 20261104), "available as a public preview". `macos-latest` is
still `macos-26`. The repo-standards skill already uses `xcode-27` as the toolchain leg for
the app repos (`audit.sh:119`).

**Options:**
- (a) `runs-on: xcode-27`. CI runs macOS 27, on a preview image.
- (b) A matrix of `macos-26` and `xcode-27`. This tests what the Mac runs and keeps a GA image.
  It also covers a new Mac that arrives on 26, as this one did. It doubles the CI minutes,
  about 4 minutes a leg.
- (c) Keep `macos-26`, and rewrite the comment to say why: there is no GA macOS 27 image until
  GitHub promotes one.

In each case the comment stops promising a bump that cannot happen.

## CC-2 — Logic Pro 12 has a new bundle name (LOW)

2026-11-25 19:06 UTC), and `/Applications/Logic Pro.app` is gone. The bundle id is still
`com.apple.logic10`, and the App Store id is still 634148309, so the link in

```
unlisted		/Applications/Logic Pro 12.app	present	docked
```

sevmac names Logic Pro only as a kind of work that Magic Backup Machine copies.

## CC-3 — Amphetamine is listed, and is not a login item (LOW, decision)

`cccbba4` (2026-11-13) added `/Applications/Amphetamine.app` to `config/login-items.txt`. Today
`sync-login-items --check` prints:

## CC-6 — `CLAUDE.md` has no row for a macOS upgrade (INFO)

CC-1 and CC-4 have one cause. `CLAUDE.md`'s tables cover the changes that a commit makes in mrk.
An OS upgrade is not a commit, and nothing listed what depends on the OS version. The reminder
in `ci.yml` was in the one file that nobody opens on upgrade day.

**Suggestion:** a row in the first table of `CLAUDE.md`. Something like: "This Mac moves to a
new major macOS → `ci.yml`'s `runs-on` and its comment; the manual's Prerequisites; MRK-1's
header; SMAC-1's and SMAC-2's SYSTEM cell; the examples of a major upgrade (CC-5); and an audit
of the Mac, as module 18 and this module did." A test that reads `sw_vers` would fail in CI,
which runs another macOS, so a row is the right tool here.

## Decisions, 2026-11-25

The owner decided the rest the same day, on the same branch:

- **CC-1: both legs.** `ci.yml` runs a `checks` job on `macos-26` and `xcode-27`, with
  `fail-fast: false`. The ruleset on `main` requires a check named `test`, and a matrix names
  its checks `checks (macos-26)` and `checks (xcode-27)`. So a `test` job on `ubuntu-latest`
  needs `checks`, runs with `if: always()`, and passes only when `needs.checks.result` is
  `success`. Without `always()`, a failed leg would skip `test`, and the rule counts a skipped
  check as passed. The comment says to move the preview leg to `macos-27` when GitHub adds
  that label.
- **CC-3: Amphetamine goes.** `sync-login-items --remove Amphetamine` deleted its line, and
  README says six login items. The app stays installed, and stays in `docs/app-store-apps.md`.
- **CC-3: Thaw is retired.** It is gone from the Brewfile, `tools/picker/descriptions.tsv`,
  `config/app-prefs.tsv`, the manual's table of managed apps, and snapshot-prefs' noise
  list. Its plist stays in mrk-prefs, as Ice's did. At the owner's word, `brew uninstall
  --cask thaw` removed the app. Homebrew then removed four formulae that nothing used:
  `curl`, `libnghttp2`, `libnghttp3` and `libngtcp2`. None is in the Brewfile, and topgrade's
  `brew autoremove` would have removed them at the next update. `curl` is now macOS's
  `/usr/bin/curl`. `sync --check` offers nothing, and mrk-status says that the Brewfile
  matches what Homebrew has installed: 54 formulae and 55 casks.
- **CC-6: the row.** `CLAUDE.md` has a new section, "When this Mac moves to a new major
  macOS". It names the CI legs, the manual's Prerequisites, MRK-1's header, the SMAC SYSTEM
  cells, and the examples of a major upgrade, then asks for an audit like this one.

**Gate:** `scripts/ci-check` on the branch with these changes, in a clone under a throwaway
HOME: exit 0, 1,088 lines marked ✓, none marked ✗. docs-drift now counts 15 managed apps and
6 login items.
