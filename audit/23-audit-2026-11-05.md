## AA-1 — `PREFS_REPO` is set in two scripts, and the fork instructions name one (MEDIUM)

`README.md:100` and `manual.md:28` say: set `PREFS_REPO` in `scripts/snapshot-prefs`. The manual
says that this is the step that "blocks everything else".

The variable has two defaults:
- `scripts/snapshot-prefs:98`: `: "${PREFS_REPO:=git@github.com:sevmorris/mrk-prefs.git}"`
- `scripts/pull-prefs:37`: the same line

Phase 3 clones through pull-prefs (`post-install:332`, `PREFS_SCRIPT="$SCRIPT_DIR/pull-prefs"`),
and so does `make pull-prefs`. A fork that follows the README or the manual pushes its snapshots
to its own repository. Then, on the next Mac, Phase 3 tries to clone `sevmorris/mrk-prefs`, which
the fork cannot read.

**Fix:** name both scripts in the two places. A better fix is one default, in `lib.sh`, which
both scripts read. Then the instruction names one place, and that is true.

## AA-2 — SMAC-1 says that Barkeep is not notarized (MEDIUM)

SMAC-1 §3.2.2, "Caution — First Launch": "The macOS blocks the application because it is not
notarized with Apple. … run `xattr -cr /Applications/Barkeep.app`."

This is false:
- §3.2.1, just above it, says that Phase 3 checks that "the app is signed by the expected
  Developer ID and notarized".
- `install-apps` refuses an app that Gatekeeper does not accept as notarized.
- On this Mac, `spctl -a -vv -t exec /Applications/Barkeep.app` gives
  `accepted`, `source=Notarized Developer ID`.
- Barkeep's `release.sh` notarizes with the `notarytool` profile.

`xattr -cr` removes the quarantine attribute, so Gatekeeper does not check the download. A
manual install from the releases page needs no command.

**Fix:** delete the caution. If a note stays, say that the app is notarized and opens normally.
